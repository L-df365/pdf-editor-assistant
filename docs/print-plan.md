# 打印功能方案（v1.4 规划）

> 目标：把「把一堆文件按各自参数打印出去」做成**独立可拆分的模块**——
> 既能从 PDF 编辑器里进入（打印当前文档/当前页），也能脱离编辑器直接用
> （选文件、选文件夹，组队列，打印）。两边共用同一套引擎与同一套界面。

## 进度

| 部分 | 状态 |
|---|---|
| 打印底座 `core/print/`（参数、页码范围解析、能力探测、作业提交） | ✅ 已完成 |
| 参数表单 `gui/print_options.py`（批量打印的逐项覆盖复用它） | ✅ 已完成 |
| **打印当前 PDF**（文件 → 打印… / Ctrl+P / 预览动作条「打印此页」） | ✅ 已完成 |
| 批量打印（队列、逐文件参数、合并拆分、状态监控、模板与历史） | ⏳ 待做，单独开发后接入 |

批量打印按独立模块开发：它有自己的窗口（`gui/print_window.py`）和队列
（`core/print/queue.py`），但**参数表单、底座、能力校验全部复用上面已经做好的部分**，
接进 PDF 助手时只是多一个入口。

## 0. 结论速览

| 需求 | 能不能做 | 怎么做 | 代价 |
|---|---|---|---|
| 队列（多文件、多格式混排） | ✅ | 队列项 = 一个待打印文件；格式无关，转换在提交前完成 | 小 |
| 队列内排序 | ✅ | 复用页面轨那套「落点线」拖拽组件（需抽成通用件） | 小 |
| 队列持久化 | ✅ | 需求说"内存级"：队列对象挂在打印窗口上，弹窗关闭不清空 | 很小 |
| 自动转 PDF（用户无感） | ✅ | 直接用现有 `core/converter.py`（WPS 静默 / LibreOffice） | 无 |
| 转换失败隔离 + 单独重试 | ✅ | 队列项级 try/except，与 `insert_files` 同一套写法 | 小 |
| **逐文件页码范围** | ✅ | CUPS `page-ranges`（已实测支持） | 小 |
| **逐文件黑白/彩色** | ✅ | CUPS `print-color-mode`（已实测支持） | 小 |
| **逐文件单双面（长边/短边）** | ✅ | CUPS `sides`（已实测支持三档） | 小 |
| 逐文件份数/纸张/缩放/N-up | ✅ | CUPS `copies` / `media` / `print-scaling` / `number-up` | 小 |
| 公共默认 + 单文件覆盖 | ✅ | 参数用 `None` 表示"继承默认"，覆盖项在行内标出来 | 中（UI 是重点） |
| 参数相同的连续文件自动合并 | ✅ | 合并成一个作业，用 `page-ranges` 表达多段 | 中 |
| 参数不同自动拆分成子任务 | ✅ | 每个子任务一个 CUPS 作业 | 中 |
| 实时队列状态 + 暂停/恢复/取消 | ⚠️ 部分 | 暂停 = 停止提交后续作业（应用层）；取消 = `cancelJob`（仅未开印的） | 中 |
| 打印前能力校验（不静默降级） | ✅ | `getPrinterAttributes()` 拿 `sides-supported` / `print-color-mode-supported` / `media-supported`，不支持就拦下 | 小 |
| 失败隔离 + 一键重试 | ✅ | 失败区 + 重试按钮 | 小 |
| 语法级混合任务（`1-12d,13s,14-*d`） | ✅ | 解析后切片，每个切片一个作业（页数奇偶要处理） | 中 |
| 按章/节打印 | ⚠️ 降级 | 本软件拿不到 Office 内部结构；改做**按 PDF 书签打印**（PyMuPDF `get_toc()`） | 中 |
| 打印模板 | ✅ | 存 `~/.config/pdf-editor-assistant/`，和后端设置同目录 | 小 |
| 任务历史与重打印 | ✅ | 存路径 + 参数快照 | 小 |
| 拖拽文件入队 | ⚠️ 降级 | Tk 没有系统级拖放 → 用「多选 + 文件夹递归」代替 | — |

**一句话**：除"拖拽入队""Office 内部结构感知""打印机级暂停"三条要降级，其余全部能在
CUPS + 现有转换后端上原生落地——因为 CUPS 的打印选项本来就是**作业级**的，
"逐文件独立参数"天然等于"拆成多个作业"。

## 1. 这台机器/这台打印机的真实能力（实测）

型号 `KONICA-MINOLTA-C368Series`，CUPS 2.3.1，`python3-cups` 1.9.73。

### 1.1 IPP 能力（`getPrinterAttributes` 实测输出）

| 属性 | 值 | 用途 |
|---|---|---|
| `sides-supported` | `one-sided` / `two-sided-long-edge` / `two-sided-short-edge` | 单双面（长边/短边）|
| `print-color-mode-supported` | `monochrome` / `color` | 黑白/彩色 |
| `media-supported` | 52 项（`iso_a4_210x297mm`、`iso_a3_297x420mm`、`na_letter_8.5x11in`…）| 纸张 |
| `number-up-supported` | `1 2 4 6 9 16` | N-up（由 pdftopdf 过滤器处理）|
| `number-up-layout-supported` | 8 种版式 | N-up 排版 |
| `page-ranges-supported` | `True` | 页码范围 |
| `print-scaling-supported` | `auto` / `auto-fit` / `fill` / `fit` / `none` | 缩放 |
| `printer-state` | `3`（idle）| 在线/忙/停机 |
| `printer-is-accepting-jobs` | `True` | 是否收单 |
| `printer-state-reasons` | `['toner-low-report']` | 缺墨提示（要显示！）|

> 注意：PPD 里 `SelectColor` 是厂商选项，但 IPP 层有标准的 `print-color-mode`，
> **按 IPP 走更稳**（换一台打印机也不用改代码）。

### 1.2 作业提交实测

用一次性测试队列（`file:` 设备，不出纸）验证过：

```python
job = conn.printFile('pdf-test', 'x.pdf', '标题', {
    'sides': 'two-sided-long-edge', 'print-color-mode': 'monochrome',
    'media': 'iso_a4_210x297mm', 'number-up': '2',
    'copies': '3', 'page-ranges': '1-3'})
# → 作业号 25，CUPS 侧读回：
#   sides=two-sided-long-edge  print-color-mode=monochrome
#   media=iso_a4_210x297mm      number-up=2  copies=3  page-ranges=(1,3)
```

**结论：所有打印参数都是一等公民的 IPP 作业属性，不必拼 `lp` 命令行。**

### 1.3 两个必须记住的限制

1. **打印选项是作业级的** → 同一份文件里"1-12 黑白双面、13 页彩色单面"这种混排，
   必须拆成多个作业（这正好是需求 4 的"自动拆分"）。
2. **跨作业的奇偶配对会断**：拆出来的每个作业各自成对，某段最后一页的背面会空。
   CUPS 在作业内部会自己补空页，但两段之间不会共享一张纸。
   → 方案：段之间按"整张纸"对齐（见 §5.3），或提示用户"混排模式会多耗纸"。

## 2. 架构：独立可拆分

```
pdf-editor-assistant/
├── core/print/                  ← 引擎：与界面无关，也不依赖 PDF 编辑器
│   ├── __init__.py
│   ├── ranges.py                ← 页码范围解析：1-5,8,10-、*、后缀 d/s/c
│   ├── options.py               ← 打印参数模型 + 默认值 + 覆盖语义
│   ├── items.py                 ← 队列项（一个待打印文件）
│   ├── jobs.py                  ← 队列 → 作业计划（合并/拆分）
│   ├── prepare.py               ← 转 PDF + 切片 + 拼版（PyMuPDF）
│   ├── printers.py              ← CUPS 能力探测、选项映射、提交/取消/查询
│   ├── queue.py                 ← 队列状态机 + 后台执行线程
│   └── history.py               ← 历史与模板（落 core/settings.py 同目录）
├── gui/print_window.py          ← 独立的打印窗口（可单独运行）
└── gui/print_panel.py           ← 队列面板控件（表格 + 默认设置 + 覆盖）
```

### 2.1 独立性怎么保证

- `core/print/**` **不 import 任何 tkinter**，也不 import `gui/`：
  可以被别的程序当库用（`from core.print.queue import PrintQueue`）。
- `gui/print_window.py` 只依赖 `core/print/**` + `gui/theme|widgets|feedback`：
  不依赖 `gui/main_window.py`。
- 打印窗口既可以**挂在别人的 root 上**（当子窗口），也可以**自己开一个 root**（独立运行）。

### 2.2 两个入口

| 入口 | 触发 | 行为 |
|---|---|---|
| **独立入口** | `pdf-editor --print` / 单独启动器 | 直接开打印窗口，空队列，用户自己加文件 |
| **应用内入口** | 顶栏「文件 → 打印…」 | 同一个打印窗口，预填当前文档（可只选当前页/页范围）|
| **页面级入口** | 预览动作条「打印此页」 | 预填当前页，直接进队列 |

三条入口走的是**同一个窗口、同一套队列**，不是三份实现。

### 2.3 入口与主程序的关系（main.py）

```python
# main.py
if args.print:                      # 独立模式：只开打印窗口
    app = PrintApp()                # 自己建 root
elif args.file:
    app = MainWindow()              # 正常模式
    app.open_file(...)
else:
    app = MainWindow()
```

打印窗口在应用内模式下是 `Toplevel`（模态或非模态由需求定），在独立模式下是主窗口。

### 2.4 与现有代码的复用

| 已有 | 打印怎么用 |
|---|---|
| `core/converter.py` `convert_to_pdf()` | 非 PDF → PDF，静默，用户无感 |
| `core/formats.py` | 支持的扩展名、徽标、类型分组 |
| `core/settings.py` | 模板/历史的落盘位置与写法照抄它的模式 |
| `gui/file_sheet.py` | 加一个「文件夹」模式 → 递归展开成队列项 |
| `gui/feedback.py` | Toast / 错误面板 / 确认面板 |
| `gui/theme.py` `gui/widgets.py` | 队列面板的视觉语言（圆角按钮、色块、卡片）|
| `gui/thumbnail_panel.py` | **抽出**落点线拖拽排序 → `gui/draglist.py`，队列面板复用 |
| `core/pdf_document.py` | 切片/拼版用 PyMuPDF 直接做，不必走 PDFDocument |

## 3. 数据模型

```python
# 打印参数：None = 继承全局默认
@dataclass
class PrintOptions:
    pages: str | None = None          # '1-5,8,10-' 或 None（全部）
    color: str | None = None          # 'color' | 'mono' | None
    duplex: str | None = None         # 'one' | 'long' | 'short' | None
    copies: int | None = None         # 1..99
    media: str | None = None          # 'iso_a4_210x297mm' | None
    scaling: str | None = None        # 'auto'|'fit'|'fill'|'none' | None
    nup: int | None = None            # 1|2|4|6|9|16 | None
    nup_layout: str | None = None     # 'btlr' 等

# 队列项：一个待打印的文件
@dataclass
class PrintItem:
    path: str
    options: PrintOptions             # 只存与默认不同的字段
    status: str                       # 待处理/转换中/待打印/打印中/完成/失败
    error: str = ''
    job_ids: list[int] = field(default_factory=list)
    pages_total: int = 0              # 转换后才知道

# 作业计划：一个真正提交给 CUPS 的作业
@dataclass
class PrintJob:
    items: list[PrintItem]
    options: PrintOptions             # 合并后的最终参数
    segments: list[Segment]           # 切片信息（页范围 + 自己的 sides）
    cups_job_id: int | None
```

**覆盖语义**：`PrintOptions` 里所有字段默认 `None`＝"用全局默认"。
队列面板上，某个队列项有非 `None` 字段就在行内标一个「已覆盖」的小徽标，
点它能看见"哪几项被改了、和默认差在哪"。

## 4. 队列与状态机

```
        ┌─────────┐  转换失败   ┌──────┐
        │ 待处理  │──────────▶│ 失败 │──重试──┐
        └────┬────┘            └──────┘         │
             │ 转换成功                          │
             ▼                                   │
        ┌─────────┐  能力校验不通过  ┌────────┐  │
        │ 待打印  │────────────────▶│  拦截  │  │
        └────┬────┘                 └────────┘  │
             │ 提交作业                          │
             ▼                                   │
        ┌─────────┐   cancelJob   ┌────────┐    │
        │ 打印中  │──────────────▶│ 已取消 │    │
        └────┬────┘               └────────┘    │
             │ CUPS 报完成/失败                  │
             ▼                                   ▼
        ┌───────┐                             ┌──────┐
        │ 完成  │                             │ 失败 │
        └───────┘                             └──────┘
```

- **执行线程**：一个后台线程按队列顺序推进；每一步（转换、提交）都通过
  `queue.Queue` 把结果投回主线程，界面只读队列状态（和现有 `_poll_tasks` 同一套路）。
- **暂停**：置一个标志，线程在"提交下一个作业前"停下。已提交的作业不动。
  （打印机级暂停要 `cups-admin` 改打印机策略，超出应用权限，不做。）
- **取消**：未开印的作业用 `cancelJob` 撤掉；队列里的"待处理/待打印"项直接丢弃。
- **实时状态**：轮询 `conn.getJobs('not-completed')` 拿 CUPS 侧状态
  （`job-state` 3=处理中 4=已停 5=已取消 6=已中止 7=已完成 8=已删除 9=保留），
  与本地队列项的状态合并显示。

## 5. 任务规划：合并与拆分

### 5.1 合并

相邻且**最终参数完全相同**的队列项 → 合成一个 CUPS 作业，
用 `page-ranges` 表达多段：`1-3,7,9-`。
（每项自己的页范围要先平移成全局页号。）

### 5.2 拆分

一个队列项内部如果页范围带**模式后缀**（Firefox 语法），必须拆：

```
1-12d, 13s, 14-*d
 └─ 双面 ─┘ └单面┘ └─双面─┘
```

→ 切成 3 段，每段一个作业（`sides` 不同）。
一段之内页数不同但模式相同 → 仍可用 `page-ranges` 合成一个作业。

### 5.3 奇偶配对（唯一的坑）

拆段后每段独立配对，段与段之间不共享纸张。
处理办法（择一，做成选项）：
- **A（默认）**：段末页留空（CUPS 作业内自动补），不额外耗纸，但段边界会多一张纸。
- **B（严格配对）**：切片时把下一段的第一页拉进上一段，让每段页数成双，
  段边界整张纸对齐——代价是页面的归属会变，需要在界面上说明。

### 5.4 N-up 与缩放

- `number-up` / `number-up-layout` 交给 CUPS 的 pdftopdf 过滤器处理，**不用自己做拼版**。
- 但"缩放"要分清两种语义：
  - 页面**内容**缩放（`print-scaling`）→ 交给 CUPS。
  - 拼版后**每页的摆放**（`number-up-layout`）→ 也是 CUPS。
- 只有一种情况要自己做拼版：**每个队列项要不同的 N-up 且要合并成一个作业**——
  那就不能合并（选项不同），拆成多个作业即可，仍然不用自己做拼版。
  → 结论：**拼版永远交给 CUPS**，本软件只负责切片。

## 6. 能力校验与打印前预检

提交前（对每个作业）：

1. **打印机在线**：`printer-state`（3=idle 4=processing 5=stopped）、`printer-is-accepting-jobs`。
2. **参数支持**：
   - `duplex` → 在 `sides-supported` 里吗？
   - `color` → 在 `print-color-mode-supported` 里吗？
   - `media` → 在 `media-supported` 里吗？
   - `nup` → 在 `number-up-supported` 里吗？
3. **不静默降级**：不支持就**拦下这一项**并说明原因
   （"该打印机不支持双面（只支持单面）"），让用户改参数或换打印机。
4. **文件预检**：文件存在吗？转出来的 PDF 页数够不够（页范围超出 → 提示并夹到实际范围）。

界面表现：队列面板上"拦截"项用琥珀色标出，点开看原因，提供「改参数」快捷入口。

## 7. 界面：队列面板

沿用现有设计系统（冷中性底 + 墨青交互 + 琥珀标记），与页面轨同一套视觉。

```
┌─ 打印 ────────────────────────────────────────────────────────────┐
│  打印机: [KONICA-MINOLTA-C368Series ▾]  状态: ● 就绪 (缺墨)        │
│                                                                  │
│  默认设置（对所有文件生效）                                        │
│  颜色 [自动▾]  单双面 [双面长边▾]  纸张 [A4▾]  份数 [1▾]          │
│  缩放 [适合页面▾]  N-up [1▾]                                      │
│                                                                  │
│  队列 (3)                                          [+ 加文件] [文件夹]│
│  ┌──────────────────────────────────────────────────────────────┐│
│  │ ⠿ 报告.pdf        1-12d   黑白  双面长边  2份   待打印    ⋯  ││
│  │ ⠿ 合同.docx       全部    彩色  单面     1份   转换中    ⋯  ││
│  │ ⠿ 签字页.pdf      13      黑白  单面     1份   已完成    ⋯  ││
│  └──────────────────────────────────────────────────────────────┘│
│                                                                  │
│  失败 (0)   进度: 2/3 文件                                        │
│                              [ 打印 (3) ]   [ 清空 ]  [ 暂停 ]     │
└──────────────────────────────────────────────────────────────────┘
```

- **队列表格**每一行 = 一个队列项；行内直接显示"这一项的最终参数"（有覆盖时用琥珀色标出）。
- **编辑单行参数**：点行尾 `⋯` → 小浮层（复用 `MenuPopover` 那套圆角浮层），
  页码范围/颜色/单双面/份数各自一行。
- **排序**：拖 `⠿` 手柄，落点线与页面轨同一组件。
- **失败区**：折叠在下方，列出失败项 + 原因 + 「重试」。
- **进度**：整体「已完成/总数」，末尾给一个汇总面板（成功 n 个、失败 m 个、耗时）。

### 7.1 "公共默认 + 单文件覆盖"的交互

- 顶部的"默认设置"改一次，队列里所有没覆盖的项跟着变（实时重算最终参数）。
- 行内覆盖过的字段显示**琥珀色**，并在浮层里提供「恢复默认」。
- 覆盖是**逐字段**的：只改颜色就只记颜色，其余仍然继承。

## 8. 页码范围语法（core/print/ranges.py）

支持：

| 写法 | 含义 |
|---|---|
| `5` | 第 5 页 |
| `1-5` | 1 到 5 |
| `10-` | 10 到末页 |
| `-5` | 首页到 5 |
| `*` | 全部 |
| `1-5,8,10-` | 组合（CUPS 原生语法） |
| `1-12d` | 1-12 页，双面 |
| `13s` | 13 页，单面 |
| `14-*d` | 14 到末页，双面 |
| `1-5c` | 1-5 页，彩色 |

- 解析器输出：`[(起, 止, 模式), ...]`，模式 ∈ {默认, 单面, 双面}。
- **后缀模式会强制拆作业**（颜色/单双面是作业级）。
- 页范围越界（超出实际页数）→ 夹到实际范围并提示。

> ⚠️ **Office 文档的"内部结构"做不到**：WPS 静默转换只给 PDF，不给 Sheet/章节结构。
> 界面上必须写清楚"页码指转换后的物理页码"。想要"按结构"只能对 PDF 用书签（见 §9）。

---

## 9. 高级功能的取舍

| 需求 | 结论 |
|---|---|
| 按章/节打印 | **降级为「按 PDF 书签打印」**：PyMuPDF `get_toc()` 读出书签，让用户勾选章节 → 合成页范围。Office 文档先转 PDF 就没有书签了（这条路走不通，得说明）|
| 打印模板 | 存 `~/.config/pdf-editor-assistant/templates.json`：`{"合同-双面黑白": {...}}`，一行套用 |
| 任务历史 | 存 `print_history.json`：时间、文件、最终参数、CUPS 作业号、结果 → "重打印"按钮 |
| 语法级混合任务 | §5.2/§5.3，页数奇偶要做对齐处理 |
| 拖拽入队 | 降级为「多选 + 文件夹递归」；若以后做系统级拖放（Tk 需要 X11 扩展或 `tkdnd`），再作为增强 |

## 10. 分期

### 第一期：能用的最小集（建议先做这个）
- `core/print/`：printer 能力探测 + 队列 + 作业规划（先不做后缀语法）+ 提交/取消/查询
- 打印窗口：独立运行 + 应用内入口（顶栏「文件 → 打印…」）
- 队列面板：多选加文件/文件夹、逐项覆盖（页码/颜色/单双面/份数/纸张/缩放/N-up）、能力校验、状态、失败重试、汇总
- 复用现有转换后端

### 第二期：效率与专业感
- 作业合并/拆分、Firefox 后缀语法、奇偶配对处理
- 打印模板、任务历史与重打印
- 按 PDF 书签选章节

### 第三期：体验
- 队列面板的排序（拖拽）、暂停/恢复
- 系统级拖放入队（可选）
- 打印结果页（每项缩略图预览）之类

## 11. 验收要点

1. 选 5 个不同格式的文件（docx/xlsx/png/pdf/txt）→ 队列 → 打印，
   转换过程无感，顺序与队列一致。
2. 其中一项双面、其中一项彩色、其中一项单双面混排 → 纸上正确。
3. 选一台只支持单面的打印机（或临时把 duplex 改成不支持的值）→ 提交前被拦下，
   明确提示原因，**不静默降级**。
4. 一个文件损坏 → 该项失败并隔离，其余照常打印完；失败项能单独重试。
5. 改了"默认设置"→ 队列里没覆盖的项参数实时跟着变。
6. 打印中关掉打印窗口 → 队列继续跑（窗口只是观察者）；重开窗口能看到进度。
7. 独立运行 `pdf-editor --print` → 不依赖任何已打开的 PDF，能独立完成一次打印。
